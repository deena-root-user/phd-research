### Why We Performed These Updates

The updates documented in this file were conducted for **four major reasons**:

#### 1. Fixing Critical Engineering & Code Bottlenecks (Code Survival)
Prior to these@ updates, the existing models contained bugs that either crashed execution or severely corrupted feature representations:
* **PyTorch Attention Memory Crash (`AndroidMalwareDet1/models.py`)**:
  * *The Problem*: Computing multi-head self-attention directly on 4,561 static Android features created an attention matrix of $4561 \times 4561 \approx 20.8 \text{ million}$ elements per head. This required $>30\text{ GB RAM}$ per batch and caused GPU/CPU Out-Of-Memory (OOM) crashes.
  * *The Update*: Added a **Gated Feature Tokenization Block** that projects high-dimensional inputs into $S=128$ bounded sequence tokens. This reduced memory usage to **$< 500\text{ MB RAM}$** while preserving attention dynamics.
* **Hardcoded `Reshape((8,8))` Feature Destruction (`AndroidMalwareDet2/model.py`)**:
  * *The Problem*: The model forcibly squashed 4,561 features down to 64 values and reshaped them into an arbitrary $8 \times 8$ grid. This destroyed feature semantics and forced Transformer layers to compute attention over arbitrary numbers.
  * *The Update*: Implemented **Dynamic Sequence Tokenization** ($S=32, D=64$), allowing self-attention to process meaningful feature tokens without arbitrary squashing.
* **Cross-Platform Compatibility**: Replaced Windows backslashes (`\`) with POSIX slashes (`/`) in `data_preparation.ipynb` to prevent `FileNotFoundError` on Linux environments.

#### 2. Shifting from Incremental Code to a PhD-Level Research Problem
* *Old Paradigm*: Testing static classification on small datasets (e.g. 70:30 random train/test splits on 1-year data). This is insufficient for a PhD dissertation.
* *New Paradigm*: **Temporal Concept Drift Resilience**. Evaluating how deep learning architectures adapt over a 12-year longitudinal dataset (**LAMDA 2013–2025**, 1M+ samples).

#### 3. Building the `TDR-AndroidMalware` Research Framework
We expanded your research codebase by building a modular PyTorch framework in `/home/luciferbughunting/research/TDR-AndroidMalware`:
1. `src/data/lamda_loader.py`: Fast multi-year Parquet dataset ingestion.
2. `src/models/domain_transformer.py`: **Domain-Aware Hierarchical Transformer (DAHT)** architecture.
3. `src/models/continual_learner.py`: Continual Experience Replay buffer engine to prevent catastrophic forgetting as Android APIs evolve.
4. `src/explainability/temporal_shap.py`: Computes the **Feature Attribution Stability Index (FASI)** to measure how explainability decays across Android OS generations.
5. `experiments/01_run_drift_benchmark.py`: Live execution driver for era-based training and testing.
